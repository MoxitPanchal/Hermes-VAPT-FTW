# LOGIC FLAW HUNTER

## WHEN TO USE
Use when applications:
- change states
- involve workflows
- use OTP
- involve transactions
- expose APIs
- contain multi-step actions

## OBJECTIVE
Identify business logic vulnerabilities.

## METHODOLOGY

1. Identify state transitions
2. Identify trusted assumptions
3. Test replay attacks
4. Test parameter tampering
5. Test role confusion
6. Test sequence bypass
7. Test alternate API paths
8. Test race conditions
9. Test hidden parameter abuse

## QUESTIONS

- What changes state?
- What is trusted?
- What can be replayed?
- What happens out of order?
- What identifier can be swapped?
- What validation only exists in UI?
- What assumptions exist?

## VERIFICATION

Always:
- replay requests
- compare responses
- verify authorization boundaries
- test alternate sequences

## FAILURE RECOVERY

If blocked:
- change order
- reuse tokens
- mutate identifiers
- try stale requests
- reuse OTP/session
